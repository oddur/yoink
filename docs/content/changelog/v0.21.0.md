### New

- **hosts:** A host can use an SSH port other than 22. Set `port:` on the host, or pass `--port` to `yoink hosts add`.
- **registry:** A `registries:` list holds credentials for more than one private registry. Each pull uses the entry that hosts its image.

### Changed

- **proxy:** A service without `networks:` no longer joins `yoink-proxy-admin` or `yoink-ingress` by default. It could reach the Caddy admin API before. Each such service redeploys one time after the upgrade.
- **registry:** Credentials go only with pulls from `registry.server`. Pulls from other registries are anonymous, so the default proxy image `caddy:2` pulls again when a private registry is set.
- **deploy:** A failed healthcheck removes every container of the failed attempt. The old containers keep running, and yoink prints the last 30 log lines.
- **audit, files:** The host audit log and the staged `files:` mounts live in `~/.local/state/yoink/` of the SSH user. A deploy user without root now works on an existing server. yoink still reads the old audit directory.
- **files:** `:rw` on a `files:` mount is a config error. These mounts were always read-only.
- **up:** `--service` without `--tag` keeps the `tag:` from the config, then uses the git short SHA.

### Fixed

- **lock:** Two deploys that start at the same time can no longer both get the deploy lock.
- **healthcheck:** The HTTP probe tries again after a probe error, and stops at once when the Docker daemon rejects the probe.
- **hooks:** yoink removes a stale hook container before the hook runs, and hook container names include the service name.
- **hooks:** `tag: {service: X}` on a hook uses the tag of service X.
- **hooks:** Hook events reach the audit log. They were dropped before.
- **ssh:** The file upload and the audit log use the `ssh_key_secret:` key, and they work with `address: local`.
- **deploy:** yoink removes extra containers of a service that is already at spec.
- **secrets:** `yoink secrets rotate` gives a re-seal command that works: `yoink secrets seal < /dev/null`.
- **tui:** `a` adds a secret in the Secrets pane, `/` filters the Resources pane, and the `?` overlay shows the real keys.
- **add:** The hint after `yoink add` is a valid command.
