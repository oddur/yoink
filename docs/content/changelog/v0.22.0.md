### New

- **secrets:** On macOS, the age key can live in the login keychain. No plaintext copy stays on disk or in backups. It is opt-in: `yoink secrets key generate --keychain` creates a key there, and `yoink secrets key import --keychain` moves a key file in. See [Keep the age key in the macOS Keychain](/docs/how-to/age-key-in-keychain).
- **secrets:** `yoink secrets key export --keychain` prints the key for a backup, and `yoink secrets key remove --keychain` deletes it.
- **secrets:** `yoink secrets key list` shows each key that yoink finds for the project and marks the one it uses. `--all` lists every yoink key on the computer.

### Changed

- **secrets:** The keychain comes after `YOINK_AGE_KEY` and `YOINK_AGE_KEY_FILE` in the lookup order, and before the key files. Without a key in the keychain, nothing changes.
- **secrets:** In an SSH session into a Mac, yoink does not open the keychain prompt. If it cannot read the key there, the error says so and names `YOINK_AGE_KEY`.
- **doctor:** `yoink doctor` shows where the age key comes from. It warns when the key is not a recipient of the config, and when a key exists in the keychain and in a key file.
- **cli:** `yoink validate`, `yoink build`, and shell completion of service names no longer decrypt `secrets.age` to resolve `address_secret:` hosts. They do not contact a host.

### Fixed

- **doctor:** A config with a sealed host address or a sealed SSH key no longer stops `yoink doctor` when the age key cannot be read. It reports the problem.
