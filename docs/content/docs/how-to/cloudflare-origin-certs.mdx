**Origin Certificates** give TLS between Cloudflare's edge and your origin hosts without ACME. For the comparison with Let's Encrypt and the multi-host behavior, see [Cloudflare Origin Certificates and Let's Encrypt](/docs/explanation/cloudflare-origin-certs).

## Prerequisites

- Cloudflare's edge is in front of your domain.
- Sealed secrets are configured. If they are not, see [Sealed secrets workflow](/docs/how-to/sealed-secrets-workflow).

## Setup

### Issue the cert in the Cloudflare dashboard [step]

1. Log in to Cloudflare. Go to your zone → SSL/TLS → Origin Server.
2. Click **Create Certificate**. Keep the defaults: ECC, 15 years, hostnames `*.example.com` + `example.com`. As an alternative, list each host explicitly.
3. Copy the **Origin Certificate** (PEM, full chain) and the **Private Key**.

### Add the cert + key to `secrets.age` [step]

```sh
yoink secrets edit
```

In the editor, add the two values. Put each PEM value in quotes, because the dotenv parser reads a multi-line value only inside quotes.

```dotenv
CF_ORIGIN_CERT="-----BEGIN CERTIFICATE-----
MIIE...
-----END CERTIFICATE-----"
CF_ORIGIN_KEY="-----BEGIN PRIVATE KEY-----
MIIE...
-----END PRIVATE KEY-----"
```

Save the file and close the editor. yoink writes the values to `secrets.age`. Commit the file.

### Wire it up in `yoink.yaml` [step]

For **one service with one certificate**, set the certificate on the service:

```yaml
services:
  - name: api
    image: ghcr.io/me/api
    tag: v1
    domain: api.example.com
    tls: cert                              # ← skip ACME, use the inline cert
    tls_cert_secret: CF_ORIGIN_CERT
    tls_key_secret: CF_ORIGIN_KEY
    run:
      port: 8080
```

For **many services with one wildcard certificate**, set the certificate in the proxy-level config:

```yaml
proxy:
  tls:
    cert_secret: CF_ORIGIN_CERT
    key_secret:  CF_ORIGIN_KEY

services:
  - name: api
    domain: api.example.com
    run: { port: 8080 }
  - name: web
    domain: example.com
    run: { port: 3000 }
  - name: admin
    domain: admin.example.com
    run: { port: 9090 }
```

Every routed service inherits the proxy-level certificate. A per-service `tls_cert_secret:` overrides it for a service that needs a different certificate.

When `proxy.tls.cert_secret` is set, ACME is off and `proxy.email:` is not necessary.

### Set the SSL mode of the zone to Full (strict) [step]

In Cloudflare, go to SSL/TLS → Overview. Make sure that the SSL mode of the zone is **Full (strict)**. In this mode, Cloudflare validates the origin certificate.

## Origin-pull mTLS (lock your origin to Cloudflare's edge)

By default, a client that knows your origin IP can send requests directly to it with a `Host:` header. Those requests bypass Cloudflare's WAF, rate limits, and bot blocks. With **origin-pull mTLS**, the origin requires a Cloudflare-signed client certificate on every connection. All other connections get a TLS handshake error.

### Add the Origin Pull CA bundle to `secrets.age` [step]

Cloudflare supplies a static CA bundle. This CA signs every certificate that the edge presents to your origin. Download the bundle and seal it in quotes:

```sh
curl -sSL https://developers.cloudflare.com/ssl/static/authenticated_origin_pull_ca.pem
yoink secrets edit
```

```dotenv
CF_ORIGIN_PULL_CA="-----BEGIN CERTIFICATE-----
<bundle contents>
-----END CERTIFICATE-----"
```

### Enable Authenticated Origin Pulls in the Cloudflare dashboard [step]

Go to SSL/TLS → Origin Server → **Authenticated Origin Pulls**. Set the toggle to on.

### Add `client_auth:` to `proxy.tls:` in `yoink.yaml` [step]

```yaml
proxy:
  tls:
    cert_secret: CF_ORIGIN_CERT
    key_secret:  CF_ORIGIN_KEY
    client_auth:
      mode: require_and_verify             # strict — reject anything not signed by the CA
      trust_pool_secret: CF_ORIGIN_PULL_CA
```

This config applies to **every** routed service. After the deploy, the TLS layer rejects each connection that does not come through Cloudflare.

| `mode:` | Behavior |
|---|---|
| `require_and_verify` (default) | The proxy rejects each connection without a valid client certificate. Use this mode. |
| `require` | The proxy requires a certificate but does not verify it. Do not use this mode. |
| `verify_if_given` | The proxy accepts anonymous connections and verifies a certificate if the client presents one. |
| `request` | The proxy requests a certificate but does not enforce it. |

### Make sure that the origin rejects direct requests [step]

Run `yoink up`. Then send a request directly to the origin IP. This request has no client certificate and must fail:

```sh
curl -v https://your-origin-ip/health -H 'Host: api.example.com'
# → tls: handshake failure
```

Send a request through Cloudflare's edge. This request must succeed:

```sh
curl https://api.example.com/health
# → 200 OK
```

## Real client IP from `CF-Connecting-IP`

Behind Cloudflare, your origin sees Cloudflare's edge IPs as the client address. Caddy access logs, Coraza, rate-limit handlers, and geo-IP then treat every request as a request from Cloudflare.

To get the real client IP, add two items to `proxy:`:

- The [`caddy-cloudflare-ip`](https://github.com/WeidiDeng/caddy-cloudflare-ip) plugin. It registers a `cloudflare` source for `trusted_proxies` and refreshes Cloudflare's IP ranges periodically.
- A `proxy.config_extra:` block. It tells Caddy to trust those ranges as proxies and to read the real IP from `CF-Connecting-IP`.

```yaml
proxy:
  email: ops@example.com
  tls:
    cert_secret: CF_ORIGIN_CERT
    key_secret:  CF_ORIGIN_KEY
    client_auth:
      mode: require_and_verify
      trust_pool_secret: CF_ORIGIN_PULL_CA
  xcaddy:
    plugins:
      - github.com/WeidiDeng/caddy-cloudflare-ip
  config_extra: |
    {
      "apps": {
        "http": {
          "servers": {
            "main": {
              "trusted_proxies": {"source": "cloudflare"},
              "client_ip_headers": ["CF-Connecting-IP"]
            }
          }
        }
      }
    }
```

<Callout type="warn">

**Use the path `apps.http.servers.main.<…>`.** The server that yoink generates has the name `main`. Upstream docs and Caddyfile-adapted output use the Caddy convention `srv0`. If you write `srv0`, the deep-merge creates a second server config that listens on nothing. Then your `trusted_proxies` config has no effect, and yoink shows no error.

</Callout>

Without the plugin, `trusted_proxies: {source: cloudflare}` fails at config load.

## Rotation

Origin certificates are valid for 15 years, but a rotation every 1 to 3 years is good practice.

### Generate a new cert in Cloudflare's dashboard [step]

Use the same procedure as for the first certificate.

### Paste the new values [step]

Run `yoink secrets edit`. Replace the values of `CF_ORIGIN_CERT` and `CF_ORIGIN_KEY` with the new values.

### Commit and redeploy [step]

```sh
git commit -am 'rotate cf origin cert'
yoink up
```

`yoink up` renders the Caddy config with the new certificate and loads it into the proxy on every host through the admin API. The proxy container does not restart.
