Run a `registry:2` container as a yoink-managed service on one of your hosts. Expose it through Tailscale. Then point `image:` at the tailnet hostname. For why this design works and what it costs, see [Image shipping](/docs/explanation/image-shipping#the-self-hosted-registry-as-a-middle-ground).

## Prerequisites

- A tailnet that only operators, CI runners, and hosts can reach. The Tailscale ACLs are the auth of the registry, so `docker login` and a registry password are not necessary.
- Every host that you deploy to is on the same tailnet, or can reach `:5000` on the registry host.

## Run the registry

### Declare the registry as a service in your `yoink.yaml` [step]

```yaml
services:
  - name: registry
    image: registry
    tag: "2"
    networks: [registry]
    run:
      port: 5000
      volumes:
        - "registry-data:/var/lib/registry"   # persistent storage
      options:
        memory: "256Mi"
```

The `registry-data` volume keeps tags across restarts.

### Start the registry [step]

```sh
yoink up --service registry
```

### Point the `image:` of your app at the tailnet hostname [step]

```yaml
services:
  - name: api
    image: registry.my-tailnet.ts.net:5000/api    # tailnet-routed registry path
    tag: dev
    build:
      context: .
```

### Use it like any registry [step]

```sh
yoink build --service api --push   # docker build → docker push to your tailnet registry
yoink up --service api          # docker pull from the tailnet registry on each host
```

## Remove old image layers

The registry has no automatic garbage collection, so old image layers accumulate. Run the [GC of the registry](https://distribution.github.io/distribution/about/garbage-collection/) inside the container at regular intervals.
