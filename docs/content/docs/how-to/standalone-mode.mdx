One `yoink up --build` builds a service and ships it to each host, with no CI and no registry. The default transport is [unregistry](https://github.com/psviderski/unregistry), which gives layer-level dedup over SSH. A tarball fallback serves air-gapped hosts. For how the transports work, see [Image shipping](/docs/explanation/image-shipping).

## Deploy with one command

### Write the config [step]

Put a `yoink.yaml` next to your `Dockerfile`:

```yaml
hosts:
  - { address: my-server, user: deploy }   # tailnet hostname

services:
  - name: my-tool
    image: my-tool                  # bare name — no registry prefix
    tag: dev
    build:
      context: .                    # `.` = same directory as yoink.yaml
    run:
      port: 8080
```

### Build, ship, and run [step]

```sh
yoink up --build                    # build + ship + run, in one command
```

### Make sure that the image arrived [step]

Make sure that the output has one `done` line for each service and host:

```
✓ api:dev → host-1     done · unregistry
✓ api:dev → host-2     done · unregistry
✓ web:dev → host-1     done · unregistry
```

### Deploy a change [step]

Edit the code. Then run `yoink up --build` with a new tag:

```sh
yoink up --build --tag my-tool=dev2
```

yoink rolls the new version. If the tag does not change, yoink reports `already at spec — no-op` and does not deploy.

If the service has no `tag:` line, `--build` uses the content digest of the built image as the tag. Then each changed build deploys without `--tag`.

## Build and deploy in two commands

If the build and the deploy must be separate steps, use the two-command form.

```sh
yoink build --service my-tool                      # docker build → tag local image as my-tool:dev
yoink up --service my-tool                         # save+load to each host
```

## Select the transport

| Value | Behavior |
|---|---|
| `--transport=auto` (default) | Uses unregistry. If unregistry fails, uses tarball and prints one warning line. |
| `--transport=unregistry` | Uses unregistry. A failure is a hard error, with no fallback. |
| `--transport=tarball` | Streams the full image over SSH. For an air-gapped host that cannot pull the unregistry image, or to debug a transport failure. |

```sh
yoink up --build --transport tarball
```

In tarball mode, a progress bar for each host shows the transferred bytes and the rate:

```
⠋ api:dev → host-1     234.5 MiB @  47.0 MiB/s (tarball)
✓ web:dev → host-1     done · 89.3 MiB (tarball)
```

## Ship every service from your local daemon

By default, yoink ships only the services that have a `build:` block. Each host pulls the other services from a registry.

`--no-registry` ships every selected service from your local docker daemon and skips all registry pulls. Use it for an offline or air-gapped deploy, or to ship a locally modified version of a public image.
